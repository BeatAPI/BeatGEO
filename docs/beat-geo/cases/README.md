# Real workflow cases

Cases explain what a user asked, what was actually performed, which evidence was saved, and what remains unknown. Start with [the BeatAPI case](./beatapi-agent/README.md).

Keep each case in its own directory with a narrative, evidence index and video outline. Retain original account evidence in the ignored local archive; the evidence index records stable paths and hashes. Product walkthroughs contain reviewed summaries, not automatic exports of private account data.

For a new recording, track whether capture actually started, which task window was recorded, and where the original clip is retained. When there was no continuous recording, say so. New filming is a reproduction and should be labeled; compressed waiting time should retain the observed duration. A page showing a historical case must not look like a live collection or trigger new work on entry.

Save failed, blocked and unknown attempts alongside successful observations. Distinguish a functional workflow test, a visibility baseline, an implemented website change and a later retest. A draft or before/after chart alone does not prove publication or improvement.
