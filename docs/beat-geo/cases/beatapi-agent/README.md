# BeatAPI：从一个网址到可检查的 GEO 工作流

实测日期：2026-10-22（北京时间）。这是本地产品工作流案例，不是 GEO 提升案例。

## 案例讲什么

用户把 beatapi.io 给到 Agent，希望通过自然语言完成项目配置、浏览器采集、对比、内容准备与监控控制。Agent 通过 MCP 保存项目和问题，让 BeatBrowser 使用已登录的真实 Chrome 采样，再把结果与草稿保存到人工工作台共用的数据里。

产品内入口：本地版侧栏「真实案例」，路径 `/app/org/<组织>/settings/cases`。页面是可切换步骤的历史回顾，不会自动执行任务或读取其他组织的实时数据。支持中英文和案例摘要下载。

## 本次实际链路

1. 从真实首页了解产品，区分第一方宣传与已经验证的能力。
2. 建立默认暂停的 BeatAPI 项目，保存两个买家问题，登记 OpenRouter、fal、Replicate 三个竞品。
3. 选取其中一个不点名 BeatAPI 的问题，完成两轮独立的 ChatGPT 浏览器采样。
4. 通过 MCP 读取已入库正文和引用，匹配问题、目标配置与品牌定义进行对比。
5. 创建关联基线的文档动作；MCP 保存并审核版本 1，再通过人工界面编辑、保存和刷新，MCP 读回版本 2，旧审核清除。界面操作由自动化浏览器执行，并非用户本人手动演示。
6. 测试监控启用与暂停，读回 24 小时间隔；结束时保持暂停，没有做跨夜监控。

采样问题：

> Which API platforms let a small development team access text, image and video AI models with one API key? Compare their capabilities and limitations, and cite sources.

| 项目 | 第一轮 | 第二轮 |
| --- | --- | --- |
| 采集耗时（含入库） | 约 8 分 59 秒 | 约 8 分 21 秒 |
| 回答字符数 | 13,838 | 14,318 |
| 保存的可见引用链接 | 23 | 25 |
| 是否提及 BeatAPI | 否 | 否 |

对比：匹配一组，缺失为零，提及率差为零。两轮之间没有修改官网，因此没有“优化后增长”的结论；一个问题的两轮样本也不能代表整体表现。账号模型/搜索模式和地区未锁定，折叠来源面板没有展开。

## 实测中保留的边界

服务端网站检查受本机代理 DNS 影响，九项检查为未知，不能显示成网站零分。初期版本冲突、用户接管与旧同步请求超时的尝试保留为失败，没有算成零曝光。长回答最终通过异步回执和查询完成入库，两条成功样本均超过八分钟。草稿尚未发布，动作尚未实施。
