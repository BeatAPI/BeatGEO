# BeatGEO：SEO / GEO 界面与使用流程

2026-11-03。实施范围：同一网站工作区，导航只称 **SEO** 和 **GEO**。不拆产品、账户、密钥或品牌数据库；SEO 不是 GEO 的前置条件。

## 参考材料与取舍

已阅读两份 Conqueror 产品与 API 拆解及用户提供的界面截图。报告中有关 DataForSEO 的文字与错误码说明其集成线索，不能证明其全部数据都来自同一供应商，更不能证明 BeatAPI 每项能力、字段和覆盖范围完全相同。定价、市场空位、获客成本及付费意愿等报告判断不作为本次实现依据。

值得借鉴的是：持续显示当前网站、按任务组织工具、输入后有明确下一步、总览指标后能进入明细、保存历史结果、从研究进入问题与行动。与 Profound 的相似处是品牌上下文与数据看板的组织方式；本轮没有对 Profound 当前产品做新的实测，也不声称功能对等。

## 网站进入后的体验

1. 现有品牌流程识别业务，由用户确认品牌、域名、竞品与问题。
2. SEO 自动带入该品牌的域名与研究上下文。用户可点击「预览网站基础数据」，只查询当前域名的概览、DR、排名词、热门页面、外链摘要和外链列表，共 6 项，不隐式扩展竞品。
3. 预览显示具体对象、接口、估算费用与预算；确认后才执行。无 Key 时引导统一连接设置。只输入域名或浏览页面不会产生付费查询。
4. 已有结果在三个模块内直接读取。用户选定一份快照，展示网站、时间、状态、来源；不跨批次拼接数字，也不把竞品数据计入本站。
5. 从关键词页面可输入主题，预览主题拓展与搜索需求；已有返回记录可本地筛选。进入「内容与问题」编辑候选、确认后加入现有 GEO 问题库。
6. GEO 继续按现有流程使用 BeatBrowser 与用户登录状态采样、保存证据、形成行动、复测。用户可直接进入 GEO。

## 当前数据视图

| 页面 | 展示 | 数据边界 |
| --- | --- | --- |
| 域名概览 | 排名词数、搜索流量估算、DR、网站访问量估算、热门页面、搜索竞品候选 | 搜索估算不是 GSC / GA 实测；两个流量口径不相加 |
| 关键词 | 本站已记录排名、关键词需求/难度/意图、页面与观测时间、主题研究入口 | 快照不是实时排名跟踪；返回行不代表所有关键词；搜索量不是 AI 提问量 |
| 外链 | 总外链、引用域名、失效外链、权威度、垃圾评分及来源/目标/锚文本明细 | 仅显示当前端点实际返回字段；DR 与权威度不同量纲；没有新增/丢失增长曲线 |
| 历史与问题 | 完整报告、已有快照对比与导出、问题编辑和加入监测 | 合成示例显著标注，不能加入真实监测；建议不等于实际需求 |

未查询、未返回、失败和未知数值分别呈现；未知不填零。所有模块的查询可再次预览，浏览快照无隐式刷新。当前筛选只筛选已经返回的记录；更多分页和每域名一条设置沿用精确查询，不伪装成已抓取全量。

## 本次之外

不引入 WordPress / Shopify、发布连接器、本地商家、地区/设备新维度、DataForSEO 采购、新付费端点或新增商业计费。现有市场与语言参数仅用于保持原查询口径。

Google OAuth 客户端绑定、真实 GSC/GA 数据、BeatAPI 权限/计费/覆盖和登录浏览器端到端验收留到下一次。后续 GEO 问题库来源与版本、采集状态、证据和复测缺口沿用 [15 项完善清单](browser-geo-plan-2026-11-03.md)，不宣称本次全部完成。
