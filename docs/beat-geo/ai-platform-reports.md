# Connected AI platform reports

Use **Visibility → AI platform reports** to connect Bing Webmaster Tools or Google Search Console, select a website saved on the brand, and synchronize its AI report. No CSV or Excel upload is required. Connecting checks access; synchronization saves observations. Neither action starts question monitoring or a recurring schedule.

AI reports use the selected BeatBrowser Chrome profile and its existing login. Ordinary Google search performance continues to use the Google OAuth connection independently. Keep Chrome and BeatGEO running during synchronization. A disconnected browser, expired login, unavailable report or changed page format produces an actionable failure; existing snapshots remain available.

The reader opens the official report, observes the responses generated by normal page navigation and saves only normalized counts and report provenance. It does not copy browser cookies or replay private request credentials. These are browser integrations, not public AI-report API integrations. Their parsers fail closed if the observed contract changes.

Bing synchronization reads dated citation counts, pages and grounding queries, following pagination before saving. Google synchronization reads AI impression history and the page rows returned by the official report; Google may limit those rows. Domain properties include subdomains, while URL-prefix properties retain their prefix scope. Platform totals are stored separately from row sums. A returned empty table is distinct from an inaccessible report.

This version reads the official default three-month view. Each snapshot records the actual date interval, property and coverage, rather than assuming Google and Bing have the same window. Comparison requires matching source, property, dimension and filters with equal-length non-overlapping periods. Missing rows remain unknown. Browser question samples, API answers, Google impressions and Bing citations are not combined into one metric.

Previously saved snapshots remain readable. Disconnect removes the local connection record, not Google/Bing authorization, Chrome login or saved reports. Removing a snapshot only removes that local snapshot. Raw account evidence and credentials remain untracked.

For a workspace whose database is already initialized and current, `pnpm local:start --skip-migrations` restarts the services without applying migrations. This option does not initialize or upgrade a database.
