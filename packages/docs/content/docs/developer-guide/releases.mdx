---
title: Versioning & Releases
description: Source validation and release boundaries for BeatGEO.
---

BeatGEO uses Changesets with fixed workspace versioning. Add a changeset for a user-facing package change; documentation-only changes and internal refactors do not require one. Maintainers apply version changes after review.

The supported installation path is the source quick start with bundled local storage. The source CLI is private. No BeatGEO npm CLI or container images are published, and inherited upstream publishing workflows are disabled.

Before a source release, run lint, workspace type checks and tests, browser contracts, and the documented isolated database regression. Validate the local setup and browser extension on each claimed platform. Unit tests and synthetic provider responses do not prove real account collection or paid-provider behavior.

Back up existing local databases and private configuration before applying schema changes. Changing the PostgreSQL major version requires an explicit data migration; do not replace a database directory with files from another major version.
