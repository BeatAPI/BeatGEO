## Development

```bash
# Run all dev servers (turbo)
pnpm dev

# Run only the web app
pnpm --filter @workspace/web dev

# Run only the worker
pnpm --filter @workspace/worker dev
```

## Building

```bash
# Build all packages
pnpm build

# Build only the web app
pnpm --filter @workspace/web build

# Type check every package
pnpm turbo check-types
```

## Testing

```bash
# Run the unit tests across every package
pnpm test

# Run the tests for scripts/, which sits outside the workspace
pnpm test:scripts
```

Storybook stories double as browser tests. They run in Vitest's browser mode, so
they need a browser installed before the first run:

```bash
pnpm --filter @workspace/web exec playwright install chromium
pnpm --filter @workspace/web test:storybook
```

The analytics stats are checked against a real Postgres. These tests migrate the
database in `TEST_DATABASE_URL` and write to it, so they refuse to run unless it
points at a local database whose name ends in `_test`:

```bash
createdb beatgeo_test
TEST_DATABASE_URL=postgres://postgres:postgres@localhost:5432/beatgeo_test \
  pnpm --filter @workspace/web test:integration
```

### End-to-End Tests

The default CI validates unit tests and PostgreSQL integration. It does not run
all Playwright deployment-mode suites. The inherited E2E orchestration workflow
is not part of this fork.

For repeatable MVP regression, select Node.js 24, install the pinned pnpm version
and dependencies, and start Docker:

```bash
pnpm test:mvp
```

This creates and migrates a disposable PostgreSQL 17 database, runs browser
collector contracts, script tests, workspace unit tests and database/queue/retest
integration, then removes the test container. Provider responses are synthetic;
this is not live browser, paid API, UI or overnight acceptance.

UI suites require a separately running **test** app with the E2E fixture data.
The app and test process must use the same disposable local database. Do not
seed an existing instance: the E2E seeder deletes data. The local wrapper checks
explicit loopback URLs and a database name ending in `_test` before running:

```bash
BASE_URL=http://localhost:3156 \
DATABASE_URL=postgres://postgres:postgres@localhost:55446/beatgeo_test \
  pnpm test:e2e-local
```

Other mode-specific commands below also assume their respective test stacks and
fixtures already exist; they do not provision a server:

```bash
# Playwright specs
pnpm test:e2e
pnpm test:e2e:cloud
pnpm test:e2e:whitelabel
pnpm test:e2e:demo

# Bruno API suites
pnpm test:api
pnpm test:api:cloud
pnpm test:api:demo
```

## Code Quality

```bash
# Check formatting, lint and import order — the same check CI runs
pnpm lint

# Fix everything Biome can fix on its own
pnpm lint:fix

# Format code with Biome
pnpm format

# Find unused exports and dependencies
pnpm knip

# Lint the hand-written OpenAPI document
pnpm lint:spec

# Check every dependency's license against the MIT-compatible allow-list
pnpm license-check
```

Always run `pnpm format` before committing to ensure consistent code style across the codebase.

## Database

`drizzle.config.ts` and the migrations live in `packages/lib`, so Drizzle runs
against that package:

```bash
# Generate a new migration after schema changes
pnpm --filter @workspace/lib exec drizzle-kit generate

# Run pending migrations
pnpm --filter @workspace/lib exec drizzle-kit migrate
```

Apply schema changes with `drizzle-kit migrate` only. See
[Architecture](/docs/developer-guide/architecture#database) for why `drizzle-kit
push` is unsafe against a deployment.

## Docker

```bash
# Build Docker images locally
beatgeo compose build

# Build without cache
beatgeo compose build --no-cache

# Build only web or worker
beatgeo compose build web
beatgeo compose build worker

# Run other docker compose commands
beatgeo compose up -d
beatgeo compose ps
beatgeo compose logs -f web
beatgeo compose down
```

## Versioning

```bash
# Create a changeset (do this before every PR)
pnpm changeset

# Apply changesets and bump versions (maintainers only)
pnpm version-packages
```

## Turborepo

The monorepo uses Turborepo for parallel task execution and caching. Most commands are defined in `turbo.json` and can be run from the repo root via `pnpm <script>`.

To run a command for a specific package:

```bash
pnpm --filter @workspace/<package-name> <command>
```
