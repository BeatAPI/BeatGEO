## Local Workspace

The current open-source edition runs locally, with `DEPLOYMENT_MODE=local`. It opens without registration, login, passwords, team invitations or organization switching. Hosted commercial editions are not currently offered. Inherited deployment-mode code does not represent a launched service.

The local service binds only to loopback and uses a private browser session with same-origin request protection. Do not expose it through a public tunnel or a reverse proxy. The existing owner is retained for a single-user database; multi-user databases are not automatically converted.

## Environment Variables

`pnpm local:setup` generates matching private configuration in root `.env` and `apps/web/.env`. Keep both files synchronized. Local setup and startup use bundled PostgreSQL; no database-mode selection is needed.

### Core Settings

| Variable | Description | Default |
|----------|-------------|---------|
| `DEPLOYMENT_MODE` | Deployment mode | `local` |
| `DATABASE_URL` | PostgreSQL connection string | Generated by CLI |
| `BETTER_AUTH_SECRET` | Secret key for session encryption | Auto-generated |
| `BEAT_GEO_ENCRYPTION_KEY` | Base64-encoded 32-byte key used to encrypt provider credentials stored in the database | Auto-generated |
| `BEAT_GEO_ENCRYPTION_KEY_OLD` | Previous encryption keys, comma-separated, kept readable during a rotation | — |
| `DISABLE_TELEMETRY` | Set to `1` to disable all telemetry. See [Telemetry](/docs/developer-guide/telemetry). | — |
| `DEFAULT_DELAY_HOURS` | How often each enabled prompt is re-run against the AI models, in hours. | `24` |
| `RUNS_PER_PROMPT` | How many times each run samples every tracked platform. Answers vary between identical calls, so several samples make a mention rate a measurement rather than an anecdote — but each one is a provider call you pay for. | `5` |

<Callout type="warn">
	Back up `BEAT_GEO_ENCRYPTION_KEY` alongside your database. Credentials stored in the database are encrypted with it and nothing else — if you lose the key, or restore a database backup onto a deployment that generated a different one, those credentials cannot be recovered and have to be entered again. BeatGEO logs an error and falls back to the provider keys in your `.env` when a stored credential will not decrypt.
</Callout>

### Rotating the encryption key

Every stored credential records which key encrypted it, so a rotation doesn't have to happen all at once:

1. Move the current value of `BEAT_GEO_ENCRYPTION_KEY` into `BEAT_GEO_ENCRYPTION_KEY_OLD`.
2. Put a freshly generated key in `BEAT_GEO_ENCRYPTION_KEY` (`openssl rand -base64 32`), and restart.

New values are encrypted under the new key while anything saved under a retired one stays readable, so nothing has to be re-entered up front. Drop `BEAT_GEO_ENCRYPTION_KEY_OLD` once every stored credential has been saved again — until then, keep it, or those credentials become unreadable and BeatGEO logs which key it is missing.

<Callout type="info">
	`RUNS_PER_PROMPT` multiplies provider spend one-for-one: at the default, one firing of one prompt
	against four platforms is twenty provider calls. Lowering it to `1` cuts the bill by five and makes
	each result a single sample, so day-to-day movement gets noisier. It applies from the next firing —
	no rescheduling needed. A value below `1`, fractional, or unparseable is ignored in favour of the
	default, so a typo cannot silently stop tracking or inflate the bill.
</Callout>

<Callout type="warn">
	`DEFAULT_DELAY_HOURS` only takes effect for prompts scheduled **after** you change it. Prompts that are already scheduled keep the cadence they were created with, even after a restart. To apply a new cadence to an existing prompt, disable it and then re-enable it under **Settings → Prompts** — re-enabling reschedules it at the current `DEFAULT_DELAY_HOURS`.
</Callout>

### AI Provider Keys

At least one provider is required for BeatGEO to track visibility. See [Providers](/docs/user-guide/providers) for a full cost/capability breakdown and recommended setups.

Brand onboarding and the Opportunities report also need one direct LLM API key — `OPENAI_API_KEY`, `OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, or `MISTRAL_API_KEY` — even if `SCRAPE_TARGETS` only uses scrapers. BeatGEO uses the first of those that's set; to pick one explicitly, set `ONBOARDING_LLM_TARGET` (e.g. `claude:anthropic-api`).

| Variable | Description |
|----------|-------------|
| `BRIGHTDATA_API_TOKEN` | BrightData token — recommended scraper for ChatGPT + Google AI Mode. [Sign up](https://get.brightdata.com/beatgeo?sid=docs) |
| `OXYLABS_USERNAME` | Oxylabs Web Scraper API username — alternative scraper for ChatGPT, Perplexity, Google AI Mode. [Sign up](https://oxylabs.go2cloud.org/aff_c?offer_id=7&aff_id=2263&url_id=32) |
| `OXYLABS_PASSWORD` | Oxylabs Web Scraper API password |
| `CLORO_API_KEY` | Cloro key — alternative scraper for ChatGPT, Perplexity, Copilot, Gemini, Google AI Mode, and Google AI Overview. [Sign up](https://cloro.dev?fpr=beatgeo&fp_sid=docs) |
| `SEARCHAPI_API_KEY` | SearchApi.io key — alternative scraper for ChatGPT, Perplexity, Copilot, Gemini, Google AI Mode, and Google AI Overview, at one flat price per search. [Sign up](https://www.searchapi.io/?via=beatgeo) |
| `OLOSTEP_API_KEY` | Olostep key — recommended scraper, powers most large-scale trackers. [Sign up](https://olostep.com/?ref=beatgeo) |
| `OPENAI_API_KEY` | OpenAI API key — enables ChatGPT (via API, not the consumer UI) |
| `ANTHROPIC_API_KEY` | Anthropic API key — enables Claude tracking |
| `OPENROUTER_API_KEY` | OpenRouter key — one key for Claude + other hosted models |
| `MISTRAL_API_KEY` | Mistral API key — enables Mistral tracking |
| `DATAFORSEO_LOGIN` | DataForSEO login — optional, enables DataForSEO targets such as `chatgpt:dataforseo:online`, `gemini:dataforseo:online`, `google-ai-mode:dataforseo:online`, and `perplexity:dataforseo:online` |
| `DATAFORSEO_PASSWORD` | DataForSEO password |
| `SCRAPE_TARGETS` | Comma-separated `model:provider[:version][:online]` entries. See [Providers](/docs/user-guide/providers#scrape_targets-format). |

## Updating Configuration

Stop the local launcher with Ctrl+C, update both private `.env` files, then run `pnpm local:start`. Do not regenerate secrets to reopen an existing workspace.

## Local Storage and Backups

The local installer uses bundled PostgreSQL 17 with `BEAT_GEO_DATABASE_MODE=embedded`. Data is stored in `.beat-geo/postgres` and its ownership record is `.beat-geo/database.json`. Stop BeatGEO before backing up both paths together with root `.env` and `apps/web/.env`. Preserve the encryption key to keep stored credentials readable.

## Existing Installations

The local installer and launcher do not start containers or take over external databases. Existing data and configuration are left unchanged. Back up and explicitly migrate existing data before changing storage modes. Advanced manual database and domain configuration is described in the [self-hosting guide](https://github.com/BeatAPI/BeatGEO/blob/main/docs/self-hosting.md).
